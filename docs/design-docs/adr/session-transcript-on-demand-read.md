## 背景

Perch 此前把「除 Claude 标题派生外不读取消息正文」写成只读不变量（`ARCHITECTURE.md`、`SECURITY.md`、`core-beliefs.md`、`FAQ.md`、`README.md`）。用户需要在不离开 Perch 的情况下查看某个会话的完整对话：现有的详情面板只有元数据，源文件正文虽在本机、采集器却按设计丢弃。这条需求与既有最小读取范围直接冲突，需要一个显式决策，而不是悄悄扩大读取面。

## 决策

- Perch 允许**按需、逐会话**读取源文件正文，且仅用于对话正文视图。读取由用户打开该会话触发，不做全量预读、不做后台索引。
- 正文只在内存中渲染：不写入 `cache.db`（缓存只保存可重建的源文件定位指针）、不写日志、不联网、关闭视图后丢弃。
- 单次快照语义：打开时读一次，不随实时刷新自动重读；只有用户点击「重新读取」才重新解析。
- 内容口径限定为用户与助手的纯文本：工具调用只折叠为计数行，不读取渲染 tool 输入/输出、思考过程与附件。
- 支持范围限定为 9 个有正文的来源；Trae CN、CodeBuddy 不提供正文，入口不出现。
- UI 不做一次性披露或常驻提示（用户明确要求）；隐私口径由本 ADR 与 `SECURITY.md` / `ARCHITECTURE.md` / `FAQ.md` 承担。
- 读取路径由 Rust 侧按任务 key 解析，前端只能提交任务 key；不新增 Tauri 插件，不引入任意路径或 URL 参数。
- 内容搜索（P1）仍保持 opt-in、未实现；本决策不启用正文索引，也不改变 `search_tasks` 的数据通道。

## 考虑过的替代方案

- **把正文写进 `cache.db` 建立内容索引**：查询快、可做正文搜索，但等于在 Perch 私有缓存里复制一份会话正文，违背「不落盘」与缓存可重建原则，拒绝。
- **为每个来源预生成正文摘要**：仍需定时读取正文，且摘要失真，拒绝。
- **只支持 JSONL 来源**：实现简单，但同一入口在不同来源间时好时坏，用户无法理解，拒绝。
- **实现全局开关 / 首次披露弹窗**：更保守，但用户明确不要额外 UI；隐私边界改由文档与命令边界约束。

## 后果

- 「不读取正文」不再是全局不变量，改为「默认不读取；用户打开对话视图时按需、只读、内存内读取」。`SECURITY.md`、`ARCHITECTURE.md`、`core-beliefs.md`、`FAQ.md`、`README.md`、`SEARCH.md` 的对应表述必须同步修订，否则文档与实现冲突。
- 新命令 `read_session_content` 进入窄命令清单；`SECURITY.md` / `ARCHITECTURE.md` 的命令数量与清单需一并更新
  （现为七个注册命令：五个既有命令 + `read_session_content` + 保留的 `set_live_refresh`，前端不再调用后者）。
- 会话正文可能含密钥或隐私内容；截图、issue、日志仍需脱敏。关闭视图即丢弃正文，不做「最近查看」缓存。
- 单会话读取受 8,000 字符 / 条、200,000 字符 / 会话上限约束，超大会话只保留最近部分，可能看不到开头。
- 源文件读取失败不视为来源扫描失败，只影响该次对话视图；不写入 `sync_state`、不改变来源状态。
