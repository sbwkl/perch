## 1. 摘要

用户要求把真实体验反馈里的 P0 / P1 全部修复。P0 聚焦常驻成本：持续写入的日志 / JSONL 源导致 3 秒 probe 后几乎连续 full scan，手动刷新与后台扫描争用同一把 engine 锁，界面缺少实时扫描状态与暂停入口。P1 聚焦真实数据规模：一次渲染 500+ 条历史任务、缺少待关注视图、搜索最多只能到达 10 条、侧栏数字 / workspace / 来源状态语义不清。P2（overlay、报告视觉统一等）仍留给用户审核。

## 2. 问题与证据

- 真实运行约 5 小时、约 790 条任务快照、11 个来源；审计记录显示日志型 / JSONL 型来源反复 live full scan，慢来源平均耗时约 9.4 秒，进程采样多次接近满载，手动刷新约 3.4 秒。
- `src-tauri/src/lib.rs` 的 3 秒循环对每个变化源立即 `engine.scan(Some(source), "live")`；`crates/perch-core/src/probe.rs` 每次都递归 WalkDir 计算全树签名；前端只有总耗时和旋转图标。
- 「更早」真实挂载 503 个任务按钮，Rust 侧 `counts.attention` 未使用；搜索真实 128 个命中只有 10 条可达；侧栏 smart list / workspace / 来源计数口径不同且随筛选变化不联动；重名 workspace 仅靠 tooltip 区分；来源新鲜度差异不可见。
- 不做的后果：Perch 作为常驻总览窗口持续耗电、卡顿，用户无法在几百条历史任务里找到需关注的任务、无法到达全部搜索命中，也难以预判点侧栏后会看到什么。

## 3. 目标与非目标

### 目标

- 常驻轻量：SQLite 仍按 3 秒检查，递归 JSONL / 日志签名按 15 秒节流；live scan 对每源做去抖 + 30 秒冷却 + 最长等待兜底；扫描完成后推迟该源的签名检查；手动刷新期间后台 live scan 不进入 engine 锁。
- 可控制 / 可观察：前端提供“暂停实时 / 恢复实时”开关；Rust 发射 `scan-status` 事件，显示正在 / 最近扫描的来源、触发方式（后台更新 / 手动）与耗时。
- 长列表可用：新增「待关注」视图；历史 / 归档 / 最近视图按 60 条分页渲染，提供“显示更多”；搜索结果返回全部命中并在弹层按 50 条分页展开。
- 数字与筛选一致：切换任务视图不再清除 workspace / 来源筛选；smart list / workspace / 来源计数联动当前视图与其它筛选；头部显示可清除的筛选 chip。
- workspace 可区分：重名 workspace 显示路径父目录，临时目录与未关联项目加可读标记并排在后；workspace 区提供输入筛选和排序说明。
- 来源健康可见：每个来源行显示状态、触发方式与最近扫描相对时间；非健康或超过一小时未扫描的项使用可读提示。
- 文档与产品规格作为当前事实源同步；历史 CHANGELOG / 设计史不改写成当前状态。

### 非目标

- 不实现 FSEvents / 操作系统级文件事件订阅，不改采集器解析逻辑，不写源数据，不迁移 cache schema。
- 不实现真正的窗口化虚拟滚动（采用分页渲染，避免一次挂载 500+ DOM）；不改任务排序规则。
- 不实现 `overlay.db`、置顶 / 标签 / 备注 / 隐藏 / 重命名、复制命令、报告主题统一、原生重做 usage-ledger 报表等 P2 项。
- 不新增远程资源、字体、脚本、Tauri fs / shell / http 插件；不开放任意 shell 命令 / URL。
- 不读取真实用户 SQLite / JSONL 做测试；demo 与截图只使用合成数据。

## 4. 行为 / AC delta

- R1（P0）：While 窗口可见且实时刷新未暂停, the system shall 每 3 秒检查 SQLite `data_version`，但 JSONL / 日志目录签名最多每 15 秒计算一次；If 某来源刚完成 live scan, then the system shall 在 30 秒冷却内跳过该来源签名检查与重复 live scan。
- R2（P0）：While 某来源被活跃 agent 持续写入, the system shall 合并连续变化（6 秒静默去抖），且最长 60 秒必须允许一次 live scan；同一来源相邻 live scan 间隔不得小于 30 秒。
- R3（P0）：When 手动刷新进行中, the system shall 阻止新的 live scan 进入 engine 锁；When 手动刷新结束, the system shall 重置 probe 基线，避免旧变化立刻触发一次额外 live scan。
- R4（P0）：When 用户点击“暂停实时 / 恢复实时”, the system shall 通过窄命令切换后台实时刷新；While 暂停中, the system shall 继续消费 / 更新变化基线但不触发 live scan；If 恢复, then the system shall 从恢复时刻建立新基线。
- R5（P0）：When 扫描开始 / 结束, the system shall 发射 `scan-status`，前端显示来源、触发方式与耗时；手动刷新与后台更新需可区分，并显示实时刷新暂停状态。
- R6（P1）：When 用户选择「待关注」, the system shall 展示失败、受阻、受限、等待中、已暂停、运行中、未读或源已删除的任务，跨最近 / 更早 / 归档；计数与列表一致。
- R7（P1）：When 任意任务视图超过 60 条, the system shall 仅渲染当前页并提供“显示更多”；When 搜索命中打开一个任务, the system shall 自动展开到该任务所在页并滚动定位。
- R8（P1）：When 搜索有 N 个命中, the system shall 返回全部 N 条并按权重 / 时间排序，弹层按 50 条分页展开；`↑` / `↓` 循环选择时应自动展开到选中项。
- R9（P1）：When 用户切换任务视图, the system shall 保留其它 workspace / 来源筛选并显示组合 chip；When 任一筛选变化, smart list / workspace / 来源侧栏数字 shall 联动显示当前口径下的可点击数量。
- R10（P1）：When workspace 名称重复, the system shall 在文字中显示可区分的路径父目录；When workspace 来自临时目录或无项目路径, the system shall 显示可读标记并排到普通项目之后；When workspace 数量超过 8, the system shall 提供输入筛选且“显示更多 / 收起”仍可用。
- R11（P1）：When 来源有 `last_scan_at`, the system shall 在来源行显示触发方式与最近扫描相对时间；If 状态非 ok 或超过 1 小时未扫描, then the system shall 用文字 / 颜色突出，不只放在 tooltip。
- 边界：demo 合成数据必须实现 `set_live_refresh` 与 `scan-status` stub；usage 不可用、空列表、报告视图、900×560 小窗口、搜索无结果、筛选叠加、刷新失败均保持现有错误处理与只读边界。

## 5. 方案

1. `probe.rs` 增加 `poll_throttled()` / `poll_at()` / `reset_baseline()` / `defer_jsonl()`，以及可单测的 `LiveScanScheduler`（去抖、冷却、最长等待）。
2. `src-tauri/src/lib.rs` 增加 `ScanControl`（暂停 / 手动标记）与 `ManualGuard`；`refresh_sources` 在扫描期间置手动标记并发出状态事件；后台线程在手动 / 暂停期间跳过 live scan，结束后重置 probe 基线；新增 `set_live_refresh` 窄命令与 `scan-status` 事件，命令集合仍固定且不接受任意命令 / URL。
3. `search.rs` 移除 10 条截断，返回全部命中；前端搜索结果按 50 条分页展开，键盘选择自动扩页，底部显示总数 / 已展示数。
4. `query.rs` 把 `counts.attention` 口径扩展为失败 / 受阻 / 受限 / 等待 / 暂停 / 运行 / 未读 / 源已删除且包含归档；前端新增「待关注」视图与一致的 predicate。
5. `App.svelte` 重构任务 / 筛选 / 计数派生：视图与筛选组合、动态计数、筛选 chip、任务分页、workspace 搜索 / 重名后缀 / 特殊目录分组、来源新鲜度文字、扫描状态条与暂停按钮。
6. `demo/` 补齐事件与命令 stub；产品规格、ARCHITECTURE / README / AGENTS / ROADMAP / CHANGELOG / SEARCH 设计文档同步当前状态。

## 8. 回滚

单分支 revert；无 cache schema 迁移、无源数据写入。`scan-status` 事件与 `set_live_refresh` 命令可由前端忽略；删除时同步回退 demo stub 与文档。搜索命中数量变化无持久化影响。

## 9. 风险与未决边界

- live 扫描的 15 秒签名节流、30 秒冷却、6 秒去抖与 60 秒最长等待是工程默认值，本次依据真实持续写入负载设定；如用户要求更强实时性，可按产品规格调整常量。
- 分页渲染不是虚拟滚动，但足以把 500+ DOM 按钮降到每页 60；后续若要窗口化渲染另开变更。
- P2 项（报告主题 / 控件统一、状态持久化、overlay.db、打开项目目录、复制命令等）不在本轮范围。
