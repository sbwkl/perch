## 1. 背景与用户反馈

本变更只做可逆的视觉与排版调整，不改数据层、命令层、缓存、只读不变量或任何来源采集行为。动机来自三处真实使用反馈：

1. **侧栏选中态过于抢眼**：任务 / Workspaces / 来源三组的选中项在 #25「界面收敛」中改为「不透明实底 + 反白文字 + 3px 左侧色条」。用户反馈整片实底存在感过强，扫列表时被选中块抢走注意力，不如改动之前的柔色底好读；来源组按品牌色出文字与色条也让「哪种颜色代表什么」重新变得需要学习。
2. **对话视图两端难辨**：用户消息与助手消息同形——都占满整行、同为左对齐，只靠底色区分，扫读时难以快速分辨谁在提问、谁在回答；长输入还会把用户消息撑满整行，挤占助手回答的阅读空间。
3. **「加载更早」位置与使用时机相反**：按钮固定在消息滚动区下方、常驻可见，平时占用视觉空间；而真正想读更早消息时，用户又得先滚到底才能点到它。

## 2. 决定的口径

### 2.1 侧栏选中态：柔色底

- 选中项改为**柔色强调背景 + 加粗标签 + 强调墨色文字与计数**；去掉不透明实底、反白文字与左侧色条（含来源组的品牌色色条规则）。
- 新增「选中墨色」主题变量：浅色主题取深一档的强调棕，在柔底上实测 **4.90:1**；深色主题沿用现有强调橙，实测 **5.31:1**。两套主题下选中标签与计数的对比度均须 **≥ 4.5:1**。
- 任务 / Workspaces / 来源三组选中样式完全一致，统一使用强调墨色，不再用品牌色当选中文字色；品牌色只保留在来源图标上。
- 选中标签维持加粗；计数值在选中态与标签同墨色，未选中态保持既有三级文字色。
- 选中态与悬停态保持可区分：悬停只是浅灰底，选中是强调色柔底。
- 三组选中逻辑、`aria-pressed`、报告视图旁路与点击规则一律不变（见第 4 节）。

### 2.2 对话视图：用户消息右侧气泡

- 用户消息靠右对齐为气泡，最大宽度约 **76%**，沿用柔色强调底；气泡内**文字左对齐**，保留既有换行与长串断词规则。
- 助手消息维持全宽中性底色；工具调用折叠行维持在左侧以浅色小字呈现，不随用户气泡右移，也不套用气泡底色。
- 对话头部（来源图标、标题、状态徽标、「继续工作 / 重新读取 / 返回」）结构与顺序不变；面板仍占第 2、3 列。

### 2.3 「加载更早」移入消息列表首行

- 按钮由消息滚动容器之外移入容器内部，成为内容**第一行**，因此只有用户**滚到顶部**时才可见；样式沿用现有按钮边框与强调色文字，去掉原来为容器外定位设置的外边距，宽度与消息列对齐。
- 单次追加量保持 **+50** 不变；剩余计数随追加递减，**剩余为 0** 时按钮完全不渲染。
- 首次打开仍定位到最新一条消息，此时按钮不在视口内；用户读完一批并滚回顶部后按钮再次出现，可连续往前读。
- 点击后阅读位置按既有 **T5 锚定**口径保持，不主动跳到顶部或底部；新加载内容出现在当前视口上方。

## 4. 本次不改动的行为

以下行为必须与改动前完全一致，验收中作为回归门控：

- 三组**单选**逻辑：组内互斥，未选中的组表示「全部」；组内点击其它项切换选中。
- **点击已选中项取消**：再次点击组内已选中项取消该组选中，该组回到「全部」。
- **三组全空**守门：若取消会导致三组全部未选中，则保持该组原选中项不变，任何时刻至少一组、至多三组有选中项。
- **`aria-pressed`**：选中为 `true`，未选中为 `false`，读屏器仍能播报筛选状态。
- **报告视图旁路**：报告视图不计入三组；进入时清空任务选中，返回时恢复原任务视图与筛选。
- **任务行 / 搜索结果 / 报告按钮**的既有选中样式：不套用侧栏新的柔色底选中态，也不出现色条。
- 对话**读取范围**与**截断阈值**：仍为 9 个正文来源、按需只读快照、单条 8,000 字符、单会话 200,000 字符、最近 50 条分页；不新增或减少来源能力。
- **正文搜索**：P1 内容搜索仍未实现，本变更不引入正文索引、缓存、导出或搜索能力。
- **T5 锚定**：首次打开定位最新消息、加载更早保持阅读位置。
- 工具调用折叠、角色顺序、来源品牌色图标、只读不变量与命令边界均不变。

## 6. 验收

每条门控同时给出正向与反向用例。自动化验收沿用现有 CDP 合成数据套件，断言用户可见事实（计算后颜色与字重、元素相对位置、滚动位置、可见性与文案），不断言实现结构。

### 6.1 正常路径

| 门控 | 正向用例 | 反向用例 |
| --- | --- | --- |
| 三组各自选中 | 任务、Workspaces、来源三组分别选中任一项时，该项背景为柔色强调底、标签加粗、标签与计数为同一强调墨色，`aria-pressed` 为 `true` | 未选中项 `aria-pressed` 为 `false`，且没有选中底色（悬停只有浅灰底） |
| 浅色 / 深色对比度 | 浅色主题选中标签与计数的对比度均 ≥ 4.5:1（实测 4.90:1）；深色主题沿用强调橙（实测 5.31:1），不低于改动前水平 | 浅色与深色下都不出现不透明实底、反白文字或左侧色条；对比度低于 4.5:1 的墨色不得上线 |
| 来源组配色统一 | 来源组选中文字与计数使用与任务 / Workspaces 组相同的强调墨色，品牌色只出现在来源图标上 | 来源组选中文字不出现品牌色，也不出现按来源差异化的选中底色 |
| 用户气泡排版 | 用户消息靠右显示为气泡，右边界贴近消息列右缘，最大宽度约 76%，气泡内文字左对齐 | 助手消息保持全宽中性底、工具调用折叠行保持左侧浅色小字，二者均不右对齐、不套用用户气泡底色 |
| 面板占位 | 对话打开时面板占第 2、3 列，侧栏保持可交互，头部结构与按钮顺序不变 | 返回或按 `Esc` 后恢复原列表与详情，不残留对话面板或选中态错位 |
| 加载按钮可见时机 | 滚动到消息列表最顶部时「加载更早」出现在首行，文案显示剩余条数 | 未到顶部（停留在会话中部或首次打开定位最新消息）时按钮不可见，不在视口内 |
| 剩余计数 | 剩余大于 0 时按钮渲染，文案与实际可加载条数一致 | 剩余为 0 时按钮完全不渲染 |
| 逐次加载 | 每次点击追加 50 条，剩余计数减少 50，反复点击直到剩余为 0 后按钮消失 | 单次点击不会一次追加全部更早消息，剩余计数不会跳过或倒挂 |

### 6.2 异常路径

| 门控 | 正向用例 | 反向用例 |
| --- | --- | --- |
| 点击取消 | 点击组内已选中项会取消该组选中，该组回到「全部」，该项 `aria-pressed` 变 `false` | 若该操作会导致三组全空，则保持原选中项不变，仍有一组 `aria-pressed` 为 `true` |
| 组内切换 | 组内点击另一项时切换选中，新项获得柔色底与加粗，旧项失去选中态 | 旧项不残留选中底色，也不保留 `aria-pressed="true"` |
| 报告视图旁路 | 进入报告视图时清空任务选中，返回时恢复原任务视图与筛选 | 报告视图不计入三组，不造成三组全空，也不改动 Workspaces / 来源选中 |
| 对话读取失败 | 源文件缺失或读取失败时，对话面板内显示一行原因，并复用头部「重新读取」 | 不弹额外提示、不自动退出、不出现白屏或卡死 |
| 空会话 / 只有工具轮 | 空会话显示既有空态原因；只有工具轮的会话显示「工具调用 N 次」行 | 不渲染空白文档、不报错，也不因气泡排版改动而整屏失败 |
| 加载后阅读位置 | 点击「加载更早」后当前阅读位置保持不变，新内容出现在当前视口上方 | 不强制跳到顶部或底部，不丢失刚才读到的上下文 |

### 6.3 边界路径

| 门控 | 正向用例 | 反向用例 |
| --- | --- | --- |
| 短会话一屏内 | 会话短于一屏且仍有更早内容时，「加载更早」作为首行在顶部直接可见 | 短会话且已无更早内容时，按钮同样不渲染，不出现可加载 0 条的按钮 |
| 连续加载至见底 | 长会话可反复滚回顶部、反复点击，剩余逐步减少直至为 0 且按钮消失 | 任意一次点击都不改变单次追加量为 50，也不改变剩余计数口径 |
| 900×560 小窗口 | 小窗口下气泡、按钮与消息列均不产生横向溢出，面板仍占第 2、3 列 | 900×560 下不出现横向滚动条，头部按钮不重叠、不溢出 |
| 主题切换 | 浅色与深色主题分别跑选中态与气泡断言，均满足口径 | 深色主题不因沿用强调橙而使选中态对比度低于改动前水平 |
| 既有兜底不变 | 文件读取失败、空会话、只有工具轮、损坏行跳过等既有兜底行为与改动前一致 | 本次排版改动不引入新的错误提示，不改变读取范围或截断阈值 |
| 既有选中样式 | 任务行、搜索结果、报告按钮的选中样式与改动前一致 | 这些位置不套用侧栏新的柔色底选中态，也不出现色条 |
